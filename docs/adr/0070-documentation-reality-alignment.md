# 0070 - Documentation and Reality Alignment Process

## Status

Accepted

## Context

README claims are mostly accurate, but they do not explain important limitations or missing paths.

## Decision

Phase 3 documentation must include:

- Verified feature checklist
- Limitations section
- Links to the completeness audit and postmortem
- Tests that cover the main claims

If a feature is not tested or not shipped, the README must not imply otherwise.

## Consequences

- Documentation becomes a product boundary, not just a narrative.

## Alternatives Considered

- Keep README lightweight and aspirational: rejected because this phase is explicitly about reality matching claims.
